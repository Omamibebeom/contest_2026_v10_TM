# 學生手冊 —— 比賽要改什麼、要做什麼

所有指令都在終端機打（樹莓派：左上角黑色方框圖示或 Ctrl+Alt+T），先進到資料夾：
```
cd ~/Desktop/contest2026_v10
```

## 零、先弄清楚兩個通道

一句話：**a 是「這是什麼顏色」，b 是「這個顏色在哪裡」。**

| 通道 | 物件在哪塊板 | 手臂做什麼 | 程式做什麼 | 程式回什麼 |
|---|---|---|---|---|
| a | 放置板（位置固定，題目指定夾哪件） | 夾起物件，舉到鏡頭與光電感測器前停 1 秒 | 辨識舉在鏡頭前的物件是什麼顏色 | IO 訊號（`IO_CODES` 那張表） |
| b | 隨機位置放置板（每次位置不同） | 送 GET 問座標，照回覆去夾 | 開場拍快照，算出每件的手臂座標 | `$x,y`（照 `PICK_ORDER` 的顏色順序，不回顏色） |

## 一、你要改的四個地方（其他檔案都不要動）

| # | 檔案 | 位置 | 填什麼 | 怎麼確認填對 |
|---|---|---|---|---|
| 1 | affine_transform.py | 作答區 1：`PIXELS` / `ARMS` | 取樣工具印出的點位，至少 3 點、建議 5 點，不可排成一直線 | `python3 affine_transform.py` 印出六個參數 |
| 2 | affine_transform.py | 作答區 2：`fit()` 裡的計算（比賽會挖空） | 照《座標轉換教學》的公式手寫：Aᵀ、(AᵀA)⁻¹、T₁、T₂、回傳 2×3 矩陣 | 同上；再拿一個取樣點代進 `pixel_to_arm`，要還原出該點的手臂座標 |
| 3 | main_contest.py | 頂端 `PICK_ORDER` | 隨機位置放置板上物件的夾取順序，填顏色名（小寫）；同色兩件就寫兩次 | 啟動主程式時，快照那幾行沒有「注意」 |
| 4 | pi_gpio_controller.py | 頂端 `IO_CODES` / `FAIL_CODE` | 放置板物件的顏色 → R2 R3 R4 訊號 | `io_test.py` 按數字鍵，手臂端讀到對的碼 |

顏色名有一條鐵則：**vision_profiles.json、PICK_ORDER、IO_CODES 三個地方的名字要一模一樣、全部小寫**。

作答區 1 還沒填完（只有 1 個點）時，`python3 affine_transform.py` 和主程式都會噴 `LinAlgError: Singular matrix`——這是正常的，代表還沒作答。

## 二、賽前準備（照順序做）

**第 1 步：調顏色**
```
python3 vision_tuner.py
```
把物件放到鏡頭下，用滑鼠拖 H、S、V 三條滑桿的左右把手（白色是選到的範圍），直到右半邊的 mask 只剩物件是白的、背景全黑。按 `s`，輸入顏色名（小寫），存檔。每個顏色都做一次（放置板和隨機板的顏色全部存在同一個檔）。H 的左把手可以拖到右把手右邊，這時範圍會變成頭尾兩段。按 `n` 可以叫回已存的顏色修改，`q` 離開。

**第 2 步：取點位**
```
python3 affine_sample_tool.py
```
放一件物件 → 畫面出現十字 → 按 `SPACE` 鎖定 → 把手臂夾爪尖端 Jog 到物件正上方 → 按 `c`，輸入顯示板的 X,Y（例 `712.3,55.8`）→ 換位置再做一次。點要鋪滿隨機位置放置板（四角＋中間），至少 3 點。取完按 `p`，把印出來的兩份清單抄進作答區 1。

**第 3 步：寫轉換公式（作答區 2），然後驗算**
```
python3 affine_transform.py
```
印出 `X = …*cx + …*cy + …` 和 `Y = …` 兩行就是成功。沒印出來看最後一行錯誤（對照第四節）。

**第 4 步：填 PICK_ORDER 和 IO_CODES**（改完存檔就好）

**第 5 步：測 IO 接線**
```
python3 io_test.py
```
按 `1`～`9` 送出 IO_CODES 裡第 1～9 個顏色的訊號，手臂端看 DI 讀到的碼對不對；`f` 送失敗碼；`0` 全關；`r` 把鏡頭現在看到的顏色送出去（和比賽動作一樣）。

**第 6 步：練習跑一次**
```
python3 main_contest.py --practice
```
有畫面，快照的每件會標出顏色。手臂可以一直重跑，取用順序用完會自動從頭來。畫面熱鍵：`r` 重拍快照、`c` 順序歸零、`q` 離開。

## 三、比賽當天（照順序做）

1. 手臂停在鏡頭畫面**外面**。
2. 跑正式指令：
   ```
   python3 main_contest.py --no-ui
   ```
3. 看終端機：
   ```
   [camera] index 0 開啟, 解析度 1280x720
   [b] 快照完成, 共 3 件:        ← 件數和顏色要對
       #0 red ...
   [main] === 階段二: 可以按手臂了 ===
   ```
   **看到「階段二」那行才按手臂。** 太早按，手臂端會顯示連線失敗。
4. 比賽中不要碰程式。手臂每送一次 GET，終端會印一行「[b] 給 red → 手臂(…)」（隨機板）；每次舉物件到鏡頭前會印「[a] 判定 … → 送 IO」（放置板）。
5. 結束後 Ctrl+C 離開。

## 四、終端最後一行 → 原因 → 怎麼辦

| 最後一行 | 原因 | 怎麼辦 |
|---|---|---|
| `LinAlgError: Singular matrix` | 作答區 1 點太少或排成一直線；或作答區 2 寫錯 | 重取點位／檢查公式 |
| `ValueError: matmul ... mismatch` | PIXELS 和 ARMS 點數不一樣 | 兩份清單數一數 |
| `[camera] 試過 [0..5] 都讀不到畫面` | 相機沒插好，或被別的程式佔住 | 插好；關掉還開著的 tuner／sample tool |
| `[camera] 注意: 不是 1280x720` | 相機解析度不對，點位會全錯 | 換回同一台相機再啟動 |
| `找不到 vision_profiles.json` | 還沒存顏色 | 做第 1 步 |
| `[b] 注意: PICK_ORDER 有 'xxx'，但快照裡沒有` | 顏色名寫錯，或快照時物件被擋住 | 對名字；手臂移出畫面按 `r` 重拍（練習模式） |
| 手臂一直收到 `$NONE` | 該顏色已經給完，或 PICK_ORDER 用完 | 正式比賽這是正常結束；練習用 `--practice` |
| 手臂座標顯示 0 | 手臂按太早，程式還沒到階段二 | 等「階段二」再按 |

---

## 五、三個絕對不要

- **相機動過不重取點位**——相機位置一變，作答區 1 全部作廢。
- **啟動主程式時手臂在畫面內**——快照會拍到手臂，物件被擋住。
- **顏色名不一致**——`Red`、`red `（多空白）都算不一樣。

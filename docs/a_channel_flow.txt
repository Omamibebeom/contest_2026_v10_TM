// a通道_圖元流程說明.txt —— a 通道在 TM Flow 要拉哪些圖元
//
// a 通道【不用 script】,全部用 TM Flow 的圖形化指令(圖元)組成。
// b 通道才用 script(tm-flow-v1-測試.txt,不需修改)。
//
// 依據:
//   3-bit 編碼表與時序 → 2025 pi_gpio_controller.py
//   IO["ControlBox"].DO / .DI[n] 語法 → TMscrip_TW 手冊 1068、1399 行官方範例
//   起始姿態與電爪開合一次 → 2025 題目卷「評分規範」
//==============================================================================


//===== 賽前接線(BCM 編號) =====
//   手臂 DO0        ──▶ 樹莓派 GPIO26   (ready:通知開始辨識)
//   樹莓派 R1(17)   ──▶ 手臂 DI0        (觸發:編碼有效,保持 7 秒)
//   樹莓派 R2(27)   ──▶ 手臂 DI1        ┐
//   樹莓派 R3(22)   ──▶ 手臂 DI2        ├ 3-bit 顏色x形狀編碼
//   樹莓派 R4(23)   ──▶ 手臂 DI3        ┘
//   光電感測器      ──▶ 手臂 DI4        (深度,不經樹莓派;腳位依現場)


//===== DI 解碼表(依 2025 說明書表 3;IN1~IN4 = DI0~DI3) =====
//   DI0   DI1 DI2 DI3   代號   物件特徵
//    1     0   0   1     A     紅色 + 三角形
//    1     0   1   0     B     紅色 + 方形
//    1     0   1   1     C     藍色 + 三角形
//    1     1   0   0     D     藍色 + 方形
//    1     1   0   1     E     綠色 + 三角形
//    1     1   1   0     F     綠色 + 方形
//    0     0   1   1     -     【辨識失敗】DI0 不會變高,靠 WaitFor 逾時後讀出
//    0     0   0   0     -     待命 / 訊號已收回


//===== 每一件 a 物件的圖元順序 =====
//
//  ┌ 1. [PTP/Line 點位] 移到題目區2 的該物件夾取點(預教點位)
//  │
//  ├ 2. [SET 圖元] 關夾爪                 IO["EndModule"].DO[1] = 1
//  │    [Wait] 0.3 秒讓夾爪確實夾住
//  │
//  ├ 3. [PTP 點位] 移到【固定校正點(檢測位)】
//  │    ※ 此點要讓物件明顯靠近鏡頭(面積夠大才過得了門檻),且完整入鏡
//  │    ※ 教這個點位時,可同時在樹莓派跑 a_channel_test.py 看畫面,
//  │      直到出現綠框與「✓ 代號」為止
//  │
//  ├ 4. [SET 圖元] 拉高 ready             IO["ControlBox"].DO[0] = 1
//  │    → 樹莓派開始 3 秒辨識
//  │
//  ├ 5. [WaitFor 圖元] 等 DI0 == 1        timeout 設 8000 ms
//  │    ※ 以拉高 ready 為 t=0:
//  │        辨識成功 → t=4 秒 DI0 拉高,保持到 t=11 秒
//  │        辨識失敗 → t=3 秒送出失敗碼 0011(DI0 維持 0),保持到 t=13 秒
//  │    ※ timeout 設 8 秒:成功時 t=4 就通過;失敗時 t=8 逾時,失敗碼還在,
//  │      手臂讀 DI1~DI3 = 0 1 1 就知道是辨識失敗。
//  │    ※ 不可設 15 秒:失敗碼 t=13 秒就收回,逾時後只會讀到全 0,分不出原因。
//  │
//  ├ 6. [IF 圖元] 在 DI0=1 的 7 秒窗內讀 DI1、DI2、DI3 → 六組分支
//  │    (可用巢狀 IF:先看 DI1,再看 DI2,再看 DI3)
//  │
//  ├ 6-1.[WaitFor 逾時的那條分支] 讀 DI1 DI2 DI3
//  │    == 0 1 1 → 辨識失敗:建議做法是把物件稍微轉個角度 / 重新對正鏡頭後
//  │                回到第 4 步再試一次(重拉 ready);或直接放到暫置區跳過。
//  │    == 0 0 0 → 樹莓派沒有回應:檢查程式是否還在跑、DO0→GPIO26 接線。
//  │
//  ├ 7. [IF 圖元] 讀光電感測器那支 DI → 深度分支(深孔 / 淺孔)
//  │    ※ 若感測器裝在別處,本步驟要先移到感測位再讀
//  │
//  ├ 8. [SET 圖元] 放下 ready             IO["ControlBox"].DO[0] = 0
//  │    ※ 這一步不可省略:樹莓派要看到 ready 回到 0 才會接受下一件的觸發
//  │
//  ├ 9. [PTP/Line 點位] 依「顏色x形狀x深度」組合 → 移到題目區3 對應點位
//  │
//  └ 10.[SET 圖元] 開夾爪                 IO["EndModule"].DO[1] = 0
//       [Line] 抬起離開
//
//  → 回到主流程,接下一件(下一件是 b 就插入 tm-flow-v1 的 script 圖元)


//===== 整體 flow 範例(題目要求 5 件:a, b, b, a, b) =====
//
//   Start
//    ├─ [起始姿態]  達明 J1~J6 = 0,0,90,0,90,0   (2025 題目卷評分規範)
//    ├─ [電爪開合一次]                            (評分規範要求)
//    ├─ 第1件 ── a 子流程(上面 1~10 步的圖元)
//    ├─ 第2件 ── [Script] 插入 tm-flow-v1-測試.txt
//    │            → script 會送 GET、拿座標、移到上方【並下降夾取】
//    │            → script 之後選手自己拉:抬起 → 依 color 判斷 →
//    │               移到題目區3 對應點位 → 開夾爪 → 抬起
//    ├─ 第3件 ── [Script] 同上
//    ├─ 第4件 ── a 子流程
//    ├─ 第5件 ── [Script] 同上
//    └─ [回原點] 回起始姿態


//===== 常見問題 =====
//
// Q: WaitFor DI0 一直等不到?
// A: 看樹莓派終端有沒有印「收到 ready」。沒印 → DO0 到 GPIO26 的接線或電位
//    有問題(跑 a_channel_test.py,右上角會即時顯示 ready 電位)。
//    有印但沒輸出 → 表示辨識沒過關,跑 a_channel_test.py 看卡在哪一關:
//    面積不足(物件再靠近)、頂點數不對、方形長寬比、或分數 < 0.70。
//
// Q: 判到錯的顏色或形狀?
// A: 顏色判錯多半是兩色的 H 區間重疊(a_channel_test.py 啟動時會提醒);
//    形狀判錯多半是反光讓遮罩破洞。用 vision_tuner.py 按 a 依現場燈光重調,
//    再用 a_channel_test.py 確認出現「✓ 代號」。
//
// Q: b 的 script 要改嗎?
// A: 不用。樹莓派回覆格式 $px,py,color,v1 取 parts[0]、parts[1] 當座標,
//    第三欄 color 是給選手判斷放置點位用的。
//
// Q: 接線和解碼表怎麼在手臂還沒接好前先驗?
// A: 樹莓派跑 a_channel_test.py,按 1~6 直接送出 A~F 的編碼、按 7 送出失敗碼,
//    對照手臂顯示板的 DI0~DI3 讀值與上面的解碼表。
//
// Q: 手臂逾時後讀到 DI 全是 0?
// A: WaitFor 的 timeout 設太長,失敗碼已經收回。改成 8000 ms。
//
// Q: 夾取順序怎麼設?
// A: b 通道的顏色順序寫在樹莓派 main_contest.py 的 PICK_ORDER;
//    a 與 b 的先後則由本 flow 上圖元的排列決定。
